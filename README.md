# RCAC Support Assistant

A question-answering assistant for Purdue's Rosen Center for Advanced Computing (RCAC). It answers researchers' questions from RCAC's own documentation, cites the exact section it used, and points to the help desk when the docs don't cover the question.

> **Independent project, not an official RCAC tool.** All documentation content comes from [RCAC Documentation](https://docs.rcac.purdue.edu) ([source](https://github.com/PurdueRCAC/RCAC-Docs)). Answers are generated by an LLM and can be wrong; check the cited page.

**Status:** in active development. The first version covers the [Purdue GenAI Studio](https://docs.rcac.purdue.edu/services/genai/) docs; the other sections (cluster user guides, storage, software) come next.

## The problem

RCAC supports thousands of researchers across many clusters (Anvil, Gautschi, Negishi, Gilbreth, Scholar and more), each with its own user guide. Many questions have a different correct answer per cluster, the docs change as systems are retired (Bell is decommissioned on Oct 31, 2026), and the same routine questions reach the help desk again and again. A useful assistant has to find the right section, stay on the right cluster, cite its source, and know when to hand off to a human.

## How it works

```
RCAC markdown docs
   |
   v
loader   -> parses YAML front matter (tags, search boost), builds page URLs
   |
   v
chunker  -> splits pages at headings, cleans MkDocs syntax, sizes chunks by tokens
   |
   v
retrieval -> picks the chunks for a question   (Day 1: hand-picked; next: search)
   |
   v
LLM      -> answers from the excerpts only, citing excerpt IDs
           (Purdue GenAI Studio, OpenAI-compatible API)
```

| Module | Job |
| --- | --- |
| `app/config.py` | All settings, read from the environment in one place |
| `app/models.py` | Pydantic models: `Page`, `Chunk`, `ChatResult` |
| `app/loader.py` | Finds docs, parses front matter, maps each file to its live URL |
| `app/chunker.py` | Splits pages into chunks with stable IDs and section anchors |
| `app/prompts.py` | The system prompt and excerpt formatting |
| `app/llm.py` | The only module that calls the model; handles rate limits and logs every call |
| `app/chat.py` | Command-line chat loop |
| `scripts/stats.py` | Chunk-size and tag-coverage statistics |

## Data models

Four Pydantic models in `app/models.py` carry data between the stages. Pydantic validates types when an object is created, so a malformed page or a bad API response fails loudly at the boundary instead of deep inside the pipeline.

```
markdown file --loader--> Page --chunker--> Section(s) --> Chunk(s) --prompt--> LLM --> ChatResult
```

**`Page`**: one markdown file from the RCAC docs, with its front matter parsed out. Built by `app/loader.py`.

| Field | Type | Example | Notes |
| --- | --- | --- | --- |
| `source_path` | `str` | `services/genai/api.md` | Path relative to `docs/` |
| `url` | `str` | `https://docs.rcac.purdue.edu/services/genai/api/` | Live page URL, following MkDocs' directory-URL rule |
| `title` | `str` | `API` | First `#` heading outside a code block |
| `tags` | `list[str]` | `["Geddes", "Purdue GenAI Studio"]` | From front matter; written by RCAC staff |
| `section` | `str` | `services` | First folder in the path |
| `product` | `str` | `genai` | Second folder, or `shared` for pages not tied to one product |
| `search_boost` | `float \| None` | `1` | RCAC's own search-ranking hint, kept for later ranking |
| `body` | `str` | | The markdown with front matter removed |

**`Section`**: a run of lines under one heading. Used inside the chunker before sections are split, merged and turned into chunks.

| Field | Type | Example | Notes |
| --- | --- | --- | --- |
| `heading_path` | `list[str]` | `["API", "Rate Limits"]` | Every heading above this section, top first |
| `level` | `int` | `2` | Heading level (`##` is 2); 0 for text before the first heading |
| `anchor` | `str` | `rate-limits` | The anchor MkDocs generates for the heading |
| `lines` | `list[str]` | | The raw markdown lines |

**`Chunk`**: one retrievable piece of a page, and the unit that is searched and cited. It copies the page's metadata so it can be filtered on its own.

| Field | Type | Example | Notes |
| --- | --- | --- | --- |
| `chunk_id` | `str` | `services/genai/api.md#rate-limits-0` | Stable across runs, so eval labels stay valid |
| `source_path`, `url`, `title`, `tags`, `section`, `product` | as on `Page` | | Copied from the page, for filtering and citations |
| `heading_path` | `list[str]` | `["API", "Rate Limits"]` | Shown to the model with each excerpt |
| `anchor` | `str` | `rate-limits` | Empty for the top of a page |
| `text` | `str` | | Cleaned markdown: admonitions, tabs and images rewritten |
| `token_count` | `int` | `145` | Counted with tiktoken `o200k_base` |
| `link` | property | `https://docs.rcac.purdue.edu/services/genai/api/#rate-limits` | The citation URL, straight to the section |

**`ChatResult`**: the outcome of one LLM call. Built by `app/llm.py` and logged as one line of `logs/llm_calls.jsonl`.

| Field | Type | Example | Notes |
| --- | --- | --- | --- |
| `text` | `str` | | The model's answer |
| `model` | `str` | `gemma4:26b-a4b` | As reported by the API |
| `input_tokens` | `int` | `695` | From the API's `usage.prompt_tokens` |
| `output_tokens` | `int` | `15` | From the API's `usage.completion_tokens` |
| `latency_ms` | `int` | `275` | Wall-clock time of the request |

## LLMs and tokenizer

| Role | Model | Details |
| --- | --- | --- |
| Answer generation | [`gemma4:26b-a4b`](https://huggingface.co/RedHatAI/gemma-4-26B-A4B-it-FP8-dynamic) on Purdue GenAI Studio | Gemma 4 26B-A4B instruct, a mixture-of-experts model (26B parameters in total, about 4B active per token), FP8-quantized and served with vLLM. 65,536-token context; accepts text and images; supports tool calling and structured output through `response_format`. |
| Default if `CHAT_MODEL` is unset | `gpt-oss:120b` on GenAI Studio | RCAC's recommended general-reasoning model, also vLLM-served with a 65,536-token context. |
| Chunk sizing | tiktoken `o200k_base` | Counts tokens locally to size chunks. It is not Gemma's tokenizer, so it is close but not exact; billing-accurate counts come from the API's reported `usage`. |
| Embeddings (planned) | To be chosen | GenAI Studio embeds its own Knowledge Base with EmbeddingGemma 300M but does not expose an embeddings API, so retrieval needs a separately hosted embedding model. |

**Why `gemma4:26b-a4b`:** it is one of the four vLLM-backed models RCAC tags as recommended, it supports the structured output and tool calling the next milestones need, and as a mixture-of-experts model it answered in 0.26 to 3.7 s in testing. Answers are generated at temperature 0.2, because a support assistant should give consistent answers rather than creative ones.

## Key decisions

- **Source markdown, not the rendered website.** The MkDocs source keeps content tabs, admonitions, code blocks and front matter intact. The site's search index flattens tabs, which loses which cluster each tabbed answer belongs to, and that distinction is the hardest part of this problem.
- **Labels from human-written metadata, not an LLM.** Each chunk carries the page's front-matter `tags` (written by RCAC staff, such as "Purdue GenAI Studio") plus `section` and `product` taken from the folder path. Pages not tied to one product are labeled `shared`. Filters should rest on deterministic data, not generated labels.
- **Chunks follow headings.** A new chunk starts at every heading outside a code block. Sections over 800 tokens are split at paragraph boundaries; sections under 50 tokens merge into the next one but keep the earlier anchor, so a citation still lands where the text starts. A code block is never split, even when it is larger than the limit.
- **MkDocs syntax is rewritten, not dropped.** Admonitions become `**Warning: Title**`, content tabs become `**Tab: Name**` (keeping per-cluster answers labeled), and images become `[Image: alt text]`.
- **Citations link to the exact section.** Chunk IDs look like `services/genai/api.md#rate-limits-0`: stable across runs (the eval set depends on them), and built from anchors that match the ones MkDocs generates on the live site.
- **Designed around the real API limits.** GenAI Studio allows 20 requests per minute per user and, when the limit is exceeded, may return JSON `null` instead of an HTTP error. `app/llm.py` treats both a 429 and a `null` body as a rate limit.
- **Every call is logged** to `logs/llm_calls.jsonl` with model, input and output tokens, and latency, so cost and speed can be measured from day one.

## Results so far

First calls with `gemma4:26b-a4b` on GenAI Studio:

| Measure | Value |
| --- | --- |
| Pages ingested | 8 (GenAI Studio docs) |
| Chunks | 51, no duplicate IDs |
| Tokens per chunk | median 180, mean 228, range 51 to 936 |
| Pages with front-matter tags | 8 of 8 |
| Latency per answer | 0.26 to 3.7 s (longer for long answers) |
| Input tokens over a 3-turn chat | 695, then 1,346, then 2,476 |

The input-token growth is the cost of a stateless model: every turn resends the whole history plus the excerpts. The chat loop now keeps only the system prompt and the last 6 messages.

A labeled evaluation set (answer accuracy, citation correctness, and whether it escalates questions the docs don't cover) comes next. Until then these numbers describe speed and cost, not answer quality.

## Run it

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
git clone https://github.com/PurdueRCAC/RCAC-Docs.git data/rcac-docs
```

Create a `.env` file in the project root (never commit it):

```
GENAI_API_KEY=your-genai-studio-key
GENAI_BASE_URL=https://genai.rcac.purdue.edu/api
CHAT_MODEL=gemma4:26b-a4b
DOCS_ROOT=data/rcac-docs/docs
```

Get a key from GenAI Studio under **Settings > Account > API Keys**. Then:

```bash
uv run pytest                    # 12 tests
uv run python scripts/stats.py   # chunk and tag statistics
uv run python -m app.chat        # chat in the terminal
```

**Docs version:** a snapshot of RCAC-Docs taken on Oct 14, 2026. Eval results are tied to a docs version, because the docs change.

## Limitations

- Covers only the GenAI Studio docs so far.
- One chunk exceeds the 800-token limit: the Ollama models table (936 tokens). A markdown table has no blank lines to split at; the fix is to split large tables by rows, repeating the header row in each part.
- Retrieval is hand-picked for now, so it answers well only about the API's authentication, requests and rate limits.
- No evaluation yet, so answer quality is unmeasured.
- Token counts for chunk sizing use tiktoken's `o200k_base`, which differs from the serving model's tokenizer; billing-accurate counts come from the API's reported usage.
